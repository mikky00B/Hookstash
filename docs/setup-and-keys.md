# Setup & Keys — what you need to run Hookstash v2

This file answers "what do I have to install, sign up for, or paste in?" for
each v2 feature. Short version: **the core product needs no keys and no
accounts.** Secrets only enter the picture when you opt in to signature
verification, and those are *your providers'* secrets, used locally.

## Always required

| Tool | Why | Get it |
|---|---|---|
| Go 1.22+ | build/run the server | https://go.dev/dl/ |
| Node.js + npm | only to rebuild the dashboard (`cd web && npm install && npm run build`) | https://nodejs.org |

## M1 — Multi-endpoint capture: nothing extra

Endpoints are created via the dashboard or CLI and stored in your local SQLite
file. No keys. When you create an endpoint you get a one-time capture token —
that's generated by Hookstash itself, not something you fetch anywhere.

## M2 — Public URL: install cloudflared (no account)

Hookstash wraps Cloudflare's **quick tunnels**, which need no Cloudflare
account and cost nothing.

Install `cloudflared` and put it on your PATH:

- Windows (winget): `winget install --id Cloudflare.cloudflared`
- Windows (scoop): `scoop install cloudflared`
- macOS: `brew install cloudflared`
- Linux: see https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/

Then just run `hookstash --public`. You get an ephemeral
`https://<random>.trycloudflare.com` URL that forwards to your local port.

Optional, only if you want a **stable** URL: create your own Cloudflare named
tunnel (requires a free Cloudflare account and a domain on Cloudflare — ~$10/yr
for the domain) and point Hookstash at it with:

```
--tunnel-url https://your-sub.example.com
# or
HOOKSTASH_TUNNEL_URL=https://your-sub.example.com
```

In that mode Hookstash displays your URL but doesn't spawn anything.

## M3/M4 — Signature Lab: your providers' signing secrets

To verify (and re-sign) signatures, Hookstash needs the **same secret the
provider uses to sign the webhook**. You supply it per endpoint in the
dashboard; it stays in your local SQLite file and is never sent anywhere.

Where each secret lives:

| Provider | What you need | Where to find it |
|---|---|---|
| Stripe | Signing secret, starts with `whsec_` (per webhook endpoint) | Stripe Dashboard → Developers → Webhooks → click your endpoint → "Sign" section. Use `stripe listen` in local dev? Then use the `whsec_...` it prints. |
| GitHub | Webhook secret (you set it when creating the webhook) | Repo/ org → Settings → Webhooks → your webhook → "Secret" field |
| Paystack | Your **secret key** (`sk_test_...` / `sk_live_...`) signs `x-paystack-signature` | Paystack Dashboard → Settings → API Keys & Webhooks |
| Flutterwave | Your **Secret hash** (you set it) | Dashboard → Settings → Webhooks → "Secret hash" field |
| Shopify | App's API secret key | Shopify Partners → your app → API keys → API secret key (or `SHOPIFY_API_SECRET`) |
| Telegram | Secret token (you set it) | `setWebhook` parameter `secret_token`, chosen by you |
| Discord | App **public key** (verification only — Discord can't be re-signed) | Discord Developer Portal → your app → "Public Key" on the General Information page |

Note the asymmetry: HMAC providers use a shared *secret* (can verify and
re-sign). Discord uses a *public* key (verify only). Flutterwave/Telegram are
static-string comparisons, not HMAC.

## Environment variables (full list)

```
HOOKSTASH_HOST          bind host, default 127.0.0.1
HOOKSTASH_PORT          port, default 4040
HOOKSTASH_FORWARD_URL   auto-forward target (optional)
HOOKSTASH_DB_PATH       SQLite path, default ~/.hookstash/hookstash.db
HOOKSTASH_LOG_LEVEL     info (default) / debug
HOOKSTASH_TUNNEL_URL    user-managed public URL to display (optional, M2)
```

## Security notes (expanded for v2)

- Everything is local by default. The only network exposure is what you enable:
  `0.0.0.0` binding or a tunnel.
- With a tunnel open, protect endpoints with capture tokens — anyone who
  guesses the URL could otherwise write into your capture list.
- Provider secrets stored for Signature Lab sit in plaintext columns in your
  local SQLite file (documented trade-off; the DB is on your machine). Don't
  commit or share `~/.hookstash/hookstash.db`.
- Captured headers contain real signature headers and sometimes auth headers;
  same caution as v1 about sharing captures or exports.
